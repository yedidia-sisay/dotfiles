## Implemented behavior

Added executable [`WorkspaceMonitorAssignment.sh`](../../hyprland/.config/hypr/scripts/WorkspaceMonitorAssignment.sh) and an `exec-once` entry in [`hyprland.conf`](../../hyprland/.config/hypr/hyprland.conf).

The watcher:

1. Waits for Hyprland IPC to become available and reads active monitors with `hyprctl -j monitors`.
2. Uses `eDP-1` as the main monitor and selects the first other active monitor as the external display.
3. Moves workspaces 1–5 to `eDP-1`; moves 6–10 to the external display when connected, or back to `eDP-1` when no external display is active.
4. Listens on Hyprland’s socket2 event socket for monitor-added and monitor-removed events, then refreshes workspace placement after a short debounce.
5. Leaves placement unchanged if `eDP-1` is not active.

The watcher only issues workspace movement commands. It does not edit or issue commands to change monitor mode, resolution, refresh, scale, layout position, or mirroring. Existing monitor configuration remains in `monitors.conf`. The environment was found to have `hyprctl`, `jq`, and `socat` available.

## User test sequence and confirmation

The user was given this safe manual test process:

1. Check workspaces 1–10 and save work before testing, since moving a workspace moves its open windows too.
2. Run `~/.config/hypr/scripts/WorkspaceMonitorAssignment.sh` in a terminal and leave it running.
3. In another terminal, inspect connected monitors and workspace placement:

   ```bash
   hyprctl -j monitors | jq -r '.[].name'
   hyprctl -j workspaces | jq -r '.[] | select(.id >= 1 and .id <= 10) | "workspace \(.id) -> \(.monitor)"'
   ```

4. Connect and disconnect the external display, wait briefly after each change, and rerun the inspection commands.
5. Stop the foreground watcher with Ctrl+C. The `exec-once` startup entry will launch it automatically on the next Hyprland login.

The user confirmed that the test sequence works. This is recorded as the user’s confirmation; the live monitor events were not independently observed by Codex because the compositor socket was unavailable from its environment.
